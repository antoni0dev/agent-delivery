Read [the shared workflow](../../../.agent-harness/WORKFLOW.md) and [the project configuration](../../../.agent-harness/PROJECT.md). These links target the installed repository layout; when reviewing this source package, use root `WORKFLOW.md` and `templates/PROJECT.md`.

Use those contracts as the source of truth. Check existing ownership before dispatch. A project is a Linear master ticket or initiative, not a repository; multiple managers can work in the same repository. Choose direct bounded workers or fresh native owner sessions according to complexity. Owner sessions may coordinate workers and report back; workers do not recursively delegate. Keep one manager per initiative and one writer per worktree. Preserve native-tool requirements for session creation and messaging authorization. Give workers and reviewers the selected knowledge cards and concrete recipes, when applicable, and maintain a resumable note. Do not invoke a legacy controller or automatically create background schedules.
